# Dumri

แพลตฟอร์มส่งอาหารที่เป็นธรรมสำหรับลูกค้า ร้านค้า และไรเดอร์ โดยเริ่มจากพื้นที่อำเภอศรีธาตุและท่าคันโท

## สถานะของโค้ดในสาขานี้

สาขานี้เป็น starter สำหรับพัฒนาและทดสอบ ยังไม่ใช่ระบบพร้อมเปิดใช้งานจริง

- สมัครสมาชิกและเข้าสู่ระบบด้วย Supabase Auth Email OTP (ชั่วคราวเพื่อทดสอบโดยไม่พึ่ง SMS/Twilio)
- ออกจากระบบและคง session เมื่อเปิดแอปใหม่
- ป้องกันเส้นทาง `/dashboard` ด้วย `ProtectedRoute`
- หน้า dashboard เรียก RPC `fn_my_profile` เพื่ออ่านโปรไฟล์ของผู้ใช้ที่เข้าสู่ระบบ
- `/demo` เป็นเส้นทางจำลองการสั่งอาหารที่เก็บสถานะไว้ในหน่วยความจำของหน้าเว็บ ไม่เขียนออร์เดอร์ลง Supabase และไม่รับชำระเงินจริง

ประเภทลูกค้า ร้านค้า และไรเดอร์ต้องอ้างอิงโปรไฟล์และสิทธิ์ที่ตรวจสอบจากฝั่งเซิร์ฟเวอร์ ไม่ใช้ปุ่มหรือข้อความบนหน้าเว็บเป็นหลักฐานการอนุญาต การอนุมัติร้านค้า/ไรเดอร์และฟังก์ชันแอดมินยังไม่ใช่ workflow ที่สมบูรณ์ใน starter นี้

## เริ่มต้นใช้งาน

ต้องมี Node.js รุ่นที่รองรับ Vite 7

1. ติดตั้ง dependencies: `npm install`
2. คัดลอก `.env.example` เป็น `.env`
3. กำหนดค่าจริงใน `.env`:

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
   ```

4. รันแอป: `npm run dev`
5. ตรวจ production build: `npm run build`

ใช้เฉพาะ URL และ publishable key ของโปรเจกต์ทดสอบที่ตั้งใจใช้งาน อย่าใส่ service-role key หรือ secret key ลงใน frontend หรือในตัวแปร `VITE_*`

## ทดสอบบัญชีที่มีอยู่

1. เปิด `/login` แล้วกรอกอีเมลของบัญชีทดสอบที่มีอยู่ใน Supabase Auth
2. รับรหัส OTP ทางอีเมล แล้วกรอกที่ `/verify-email` (ต้องตั้งค่า Email OTP template ให้แสดง `{{ .Token }}` ใน Supabase)
3. การสมัครใหม่ใช้ชื่อ อีเมล และเบอร์โทรศัพท์สำหรับติดต่อ; OTP ส่งทางอีเมล ไม่ได้ส่ง SMS
4. ตรวจว่าแอปเปิด `/dashboard` และอ่านโปรไฟล์ที่เชื่อมกับบัญชีผ่าน `fn_my_profile` ได้
5. ออกจากระบบ แล้วทำซ้ำกับบัญชีทดสอบแต่ละบทบาท
6. ถ้าเข้าสู่ระบบได้แต่ไม่พบโปรไฟล์ ให้ตรวจการเชื่อมโยง Auth UID กับโปรไฟล์ก่อน ห้ามสร้างหรือแก้บัญชีจริงโดยอัตโนมัติเพียงเพื่อให้การทดสอบผ่าน

การทดสอบ Auth จริงต้องใช้ช่องทาง OTP ที่ผู้ดูแลบัญชีเข้าถึงได้ ห้ามแชร์ OTP, access token, รหัสผ่าน หรือเอกสารยืนยันตัวตนใน issue หรือแชต

หมายเหตุ: การเปลี่ยนโค้ดนี้ไม่เปลี่ยน Supabase Auth settings ให้เอง ต้องตรวจสอบ Email provider และ Email OTP template ใน Dashboard ก่อน และยังไม่ได้เปิด Phone provider หรือเปลี่ยนการตั้งค่าระบบจริง

ดูขั้นตอนเพิ่มเติมที่ [คู่มือทดสอบ Auth และ Demo](docs/manual-auth-and-demo-test-checklist.md)

## ข้อควรระวังด้านความปลอดภัย

- `ProtectedRoute` ป้องกันเฉพาะการนำทางใน UI ไม่ใช่ขอบเขตความปลอดภัยของข้อมูล
- การอ่าน/เขียนข้อมูลต้องถูกจำกัดด้วย RLS และ policies ที่ตรวจ ownership/role ในฐานข้อมูล และ RPC ต้องตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกครั้ง
- ห้ามใช้ `user_metadata` ที่ผู้ใช้แก้ไขได้เป็นหลักฐานอนุญาตสิทธิ์
- Dumri ใช้ Supabase project เดียวกับแอป Midnight Meals ในช่วงที่ยังแชร์โปรเจกต์อยู่ การเปลี่ยน schema, grants, policies, Auth, Storage หรือข้อมูลจริงต้องผ่านการตรวจผลกระทบและได้รับอนุมัติก่อน
- การผ่าน build ไม่ได้ยืนยันว่าการเข้าสู่ระบบ, RLS, RPC authorization, การชำระเงิน หรือการแยกข้อมูลระหว่างแอปปลอดภัยแล้ว

## ขั้นตอนถัดไป

ตรวจ schema และ RLS ที่มีอยู่ใน Supabase ก่อน จากนั้นเชื่อม Auth user กับโปรไฟล์ที่มีอยู่สำหรับลูกค้า ร้านค้า ไรเดอร์ และแอดมิน โดยไม่สร้างตารางซ้ำหรือเปลี่ยน schema แบบเหมารวม
